## ChronoFrame

美观、极简的自托管相册程序：上传照片后自动解析 EXIF、生成缩略图、在地图上按拍摄地点浏览，并支持相册、搜索与分享。整个应用只有一个容器，照片信息保存在容器内的 SQLite 数据库里，不需要额外部署数据库。

- 默认端口：`6231`（容器内 `3000`）
- 官方项目：<https://github.com/HoshinoSuzumi/chronoframe>
- 中文文档：<https://github.com/HoshinoSuzumi/chronoframe/blob/main/docs/zh/guide/getting-started.md>

## 数据持久化

应用的安装目录下的 `data/` 会挂载到容器内的 `/app/data`，其中包含：

| 路径 | 内容 |
| --- | --- |
| `data/app.sqlite3` | 照片信息、相册与全部站点设置 |
| `data/.session-password` | 自动生成的会话密钥 |
| `data/storage/` | 使用本地存储时的原图与缩略图 |

升级镜像只替换容器，以上数据不会丢失。备份应用目录即可备份整个相册；如果改用 S3 或 OpenList，原图在外部服务里，需要另外备份。**不要删除 `data` 目录来「重装」。**

## 首次启动

1. 安装完成后打开 `http://服务器IP:6231`，首次访问会自动进入设置向导。
2. 依次填写管理员邮箱、用户名和密码，然后填写站点名称、介绍、作者与头像。
3. 存储选择「本地存储」时，路径填写 `/app/data/storage`，照片就会保存在数据卷里；也可以在这里或之后改为 S3 兼容存储、OpenList。
4. 地图可以选择 MapLibre（MapTiler 令牌）或 Mapbox，令牌可以稍后在后台补充。

向导结束后进入 `/dashboard`，之后所有设置都在后台修改，**不需要再填写任何环境变量**。

## 配置说明

从 1.0 开始，站点信息、存储、地图、上传大小、语言等设置全部保存在数据库里，由后台维护，因此本应用只保留了端口一个安装项。旧的 `CFRAME_ADMIN_*`、`NUXT_*` 环境变量仍能被镜像读取，但只作为首次向导的预填值，优先级低于后台设置。

反向代理场景注意两点：

- 上传大小上限要与后台「系统设置」里的上传限制保持一致，Nginx 参考 `client_max_body_size 256M;`，并保留流式响应（`proxy_buffering off;`），实时日志才能正常显示。
- `NUXT_TRUST_PROXY` 是唯一仍需通过环境变量设置的部署项，默认关闭。只有在容器端口仅能被可信代理访问、且代理会覆盖 `X-Forwarded-For` 时才需要启用，否则客户端可以伪造 IP。需要时可在 1Panel 的「容器」→「编排」里为该服务补上 `NUXT_TRUST_PROXY: "true"`。

## 从 1.0.2 升级

1.0.2 及更早版本通过环境变量初始化管理员、站点和存储。这些值在首次设置完成后已经写入数据库，升级到 1.2.0 后：

- 安装表单不再显示管理员、站点、存储、地图、会话密码等字段，升级时它们不会再被注入容器；
- 已有的管理员账号、站点设置和照片都不受影响，直接用原账号登录即可；
- 只有在 `data` 目录被清空或重新安装时，才会重新进入设置向导。

## 反向代理与 HTTPS

在 1Panel 中用「网站」→「反向代理」指向 `http://127.0.0.1:6231` 即可申请证书并启用 HTTPS。若代理运行在容器里，让代理通过 1Panel 网络访问 `http://<容器名>:3000`，不必暴露宿主机端口。
